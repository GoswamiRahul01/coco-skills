# Arquetipos de Cocothon

Menú de configuraciones pre-armadas para acelerar el Paso 1. Si el usuario quiere ir rápido, ofrece estos arquetipos como punto de partida. Puede ajustar cualquier campo después.

---

## Cómo usar

Presenta al usuario la tabla resumen y pregunta: *"¿Alguno de estos se parece a lo que buscas?"*

Si elige uno, pre-llena la configuración y confirma antes de avanzar al Paso 2.

| # | Arquetipo | Duración | Equipos | Ownership | Ideal para |
|---|-----------|----------|---------|-----------|------------|
| 1 | Standard-SnowflakeLed | 3-4h | 4-6 | Snowflake define los retos | Prospects en discovery, demos de capacidad |
| 2 | Standard-CustomerLed | 3-4h | 4-6 | Cliente propone sus casos | Clientes con backlog de casos de uso claros |
| 3 | Standard-Mix | 3-4h | 4-6 | Snowflake + Cliente | Relaciones establecidas, co-creación |
| 4 | FullDay-CustomerLed | 6-8h | 5-8 | Cliente propone sus casos | Workshops de innovación, executive buy-in |
| 5 | Sprint-SnowflakeLed | 90 min | 2-4 | Snowflake define los retos | Activación rápida, wow factor, eventos cortos |
| 6 | Extended-CustomerLed | 2-3 días | 6-10 | Cliente propone sus casos | Programas multi-caso, producción real |

## Detalle por Arquetipo

### 1. Standard-SnowflakeLed

**Contexto**: El formato más común. Snowflake diseña problem statements alineados a la industria del cliente. Ideal cuando el prospect aún no tiene claridad sobre qué resolver con Snowflake.

| Campo | Valor |
|-------|-------|
| Modalidad | Standard |
| Duración | 3-4 horas |
| Equipos sugeridos | 4-6 (3-4 personas c/u) |
| Ownership PS | Snowflake-Led |
| Formato típico | Presencial |
| Datos | Sintéticos (preparados por SE) |
| Pre-evento | 1-2 semanas |
| Countdown clave | D-14: PS listos, D-7: datos cargados, D-2: briefing equipos |

**Cuándo elegirlo**:
- Prospect en etapa de discovery/qualification
- Cliente sin backlog técnico definido
- Se quiere demostrar capacidad de la plataforma
- El AE quiere controlar la narrativa del evento

**Agenda tipo**:
```
0:00-0:15  Kick-off + reglas
0:15-0:30  Ideación por equipo
0:30-2:30  Build con Cortex Code
2:30-2:45  Demo prep
2:45-3:30  Show & Tell (5 min/equipo)
3:30-4:00  Deliberación + premios
```

### 2. Standard-CustomerLed

**Contexto**: El cliente ya tiene problemas identificados y quiere resolverlos con Snowflake. Requiere una fase de curación previa (Paso 1C) para validar que los casos sean factibles en el tiempo disponible.

| Campo | Valor |
|-------|-------|
| Modalidad | Standard |
| Duración | 3-4 horas |
| Equipos sugeridos | 4-6 (3-4 personas c/u) |
| Ownership PS | Customer-Led |
| Formato típico | Presencial o Híbrido |
| Datos | Reales del cliente (preferido) o sintéticos |
| Pre-evento | 2-3 semanas (incluye curación) |
| Countdown clave | D-21: recopilar casos, D-14: curar y validar, D-7: datos listos, D-2: briefing |

**Cuándo elegirlo**:
- Cliente con backlog de mejoras/automatizaciones
- Ya hay relación técnica establecida (SE conoce el entorno)
- El cliente quiere resolver SUS problemas, no demos genéricas
- Hay sponsor ejecutivo que quiere ver resultados internos

**Agenda tipo**:
```
0:00-0:15  Kick-off + contexto del cliente
0:15-0:30  Cada equipo presenta su caso (2 min)
0:30-2:30  Build con Cortex Code
2:30-2:45  Demo prep
2:45-3:30  Show & Tell (5 min/equipo)
3:30-4:00  Deliberación + next steps reales
```

### 3. Standard-Mix

**Contexto**: Modelo híbrido donde Snowflake propone algunos retos (industry-aligned) y se deja espacio para que equipos del cliente traigan los suyos. Buen balance entre control y ownership del cliente.

| Campo | Valor |
|-------|-------|
| Modalidad | Standard |
| Duración | 3-4 horas |
| Equipos sugeridos | 4-6 (3-4 personas c/u) |
| Ownership PS | Mix (50/50 o 60/40) |
| Formato típico | Presencial |
| Datos | Mix: sintéticos para PS de Snowflake, reales para PS del cliente |
| Pre-evento | 2 semanas |
| Countdown clave | D-14: PS Snowflake listos + solicitar PS del cliente, D-7: curar todo, D-2: briefing |

**Cuándo elegirlo**:
- Relación intermedia — ni prospect frío ni cliente maduro
- Se quiere mostrar art of the possible + resolver algo real
- Hay algunos participantes técnicos que ya tienen ideas
- El AE quiere asegurar demos impresionantes (PS Snowflake) + relevancia (PS cliente)

**Agenda tipo**:
```
0:00-0:15  Kick-off: retos Snowflake + retos cliente
0:15-0:30  Equipos eligen o proponen su reto
0:30-2:30  Build con Cortex Code
2:30-2:45  Demo prep
2:45-3:30  Show & Tell (5 min/equipo)
3:30-4:00  Deliberación + premios
```

### 4. FullDay-CustomerLed

**Contexto**: Workshop de innovación de día completo. El cliente trae múltiples desafíos estratégicos. Incluye breaks, sesiones de mentoría intermedia, y una fase de refinamiento antes del pitch final. Ideal para generar executive buy-in.

| Campo | Valor |
|-------|-------|
| Modalidad | Full Day |
| Duración | 6-8 horas |
| Equipos sugeridos | 5-8 (3-5 personas c/u) |
| Ownership PS | Customer-Led |
| Formato típico | Presencial (obligatorio para engagement de día completo) |
| Datos | Reales del cliente |
| Pre-evento | 3-4 semanas (curación extensa) |
| Countdown clave | D-28: kickoff planning, D-21: PS curados, D-14: datos cargados, D-7: dry-run, D-1: briefing final |

**Cuándo elegirlo**:
- Executive sponsor comprometido (VP/C-level asiste)
- Se busca producir MVPs que realmente se lleven a producción
- Hay presupuesto de tiempo del equipo del cliente
- El AE quiere un "momento transformador" en la relación

**Agenda tipo**:
```
0:00-0:30  Kick-off ejecutivo + visión
0:30-1:00  Cada equipo presenta su caso + approach
1:00-3:00  Build Sprint 1
3:00-3:30  Break + mentoría rápida SE
3:30-5:30  Build Sprint 2 (refinamiento)
5:30-6:00  Demo prep
6:00-7:00  Show & Tell (7 min/equipo)
7:00-7:30  Deliberación + premios
7:30-8:00  Cierre ejecutivo + next steps
```

### 5. Sprint-SnowflakeLed

**Contexto**: Formato corto y de alto impacto. Snowflake prepara 2-4 retos muy acotados que se pueden resolver en 60 minutos de build. Perfecto para eventos donde hay poco tiempo pero se quiere generar wow factor.

| Campo | Valor |
|-------|-------|
| Modalidad | Sprint |
| Duración | 90 minutos |
| Equipos sugeridos | 2-4 (2-3 personas c/u) |
| Ownership PS | Snowflake-Led |
| Formato típico | Presencial o Virtual |
| Datos | Sintéticos (pre-cargados, listos para usar) |
| Pre-evento | 1 semana |
| Countdown clave | D-7: PS + datos listos, D-2: confirmación logística, D-0: go |

**Cuándo elegirlo**:
- Slot corto dentro de un evento más grande (SKO, QBR, offsite)
- Activación de trial accounts
- Demo competitiva: "mira lo que Snowflake hace en 60 min"
- Audiencia no técnica que necesita ver velocidad

**Agenda tipo**:
```
0:00-0:10  Kick-off rápido + reglas
0:10-0:15  Equipos eligen reto
0:15-1:15  Build con Cortex Code
1:15-1:25  Demos rápidas (3 min/equipo)
1:25-1:30  Ganador + cierre
```

---

### 6. Extended-CustomerLed

**Contexto**: Programa multi-día para cuentas estratégicas. Cada día puede tener un tema distinto (día 1: data engineering, día 2: AI/ML, día 3: apps). Los equipos iteran y refinan. Se busca producción real, no solo prototipos.

| Campo | Valor |
|-------|-------|
| Modalidad | Extended |
| Duración | 2-3 días |
| Equipos sugeridos | 6-10 (4-5 personas c/u) |
| Ownership PS | Customer-Led |
| Formato típico | Presencial (residencial ideal) |
| Datos | Reales del cliente (datasets completos) |
| Pre-evento | 4-6 semanas (planning extenso) |
| Countdown clave | D-42: alignment con sponsor, D-28: PS finales, D-14: datasets + entornos, D-7: dry-run, D-1: briefing |

**Cuándo elegirlo**:
- Cuenta estratégica con commitment ejecutivo fuerte
- Objetivo: producir skills/apps/agents que van a producción post-evento
- Hay un equipo técnico del cliente dedicado
- Se combina con training/enablement formal

**Agenda tipo (por día)**:
```
DÍA 1:
  09:00-09:30  Kick-off + visión del programa
  09:30-10:00  Problem Statement deep-dive
  10:00-13:00  Build Sprint 1
  13:00-14:00  Almuerzo
  14:00-17:00  Build Sprint 2
  17:00-18:00  Retrospectiva del día

DÍA 2:
  09:00-09:30  Recap + ajustes
  09:30-13:00  Build Sprint 3 (refinamiento)
  13:00-14:00  Almuerzo
  14:00-16:00  Build Sprint 4 (producción)
  16:00-17:00  Peer review cruzado
  17:00-18:00  Demo prep

DÍA 3 (si aplica):
  09:00-10:00  Final build + polish
  10:00-12:00  Show & Tell ejecutivo
  12:00-13:00  Deliberación + premios + roadmap
```

## Personalización Post-Selección

Después de que el usuario elige un arquetipo, confirma los valores pre-llenados y permite ajustes:

1. **Empresa/Industria** — Siempre debe llenarse manualmente
2. **Fecha** — Siempre debe llenarse manualmente
3. **# Equipos** — Puede ajustarse dentro del rango sugerido
4. **Formato** — Puede cambiarse (ej: Sprint presencial → virtual)
5. **Datos** — Puede cambiarse (ej: Standard-SnowflakeLed con datos reales si están disponibles)

Una vez confirmado, procede directamente al Paso 2 (Problem Statements) con la configuración pre-llenada.
