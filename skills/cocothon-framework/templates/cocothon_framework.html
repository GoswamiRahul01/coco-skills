1. ¿Qué es una Cocothon?

Una Cocothon es un hackathon estructurado (mínimo 3 horas) diseñado para clientes y prospectos, donde equipos mixtos (negocio + técnicos) resuelven problemas reales de su organización utilizando Cortex Code (Coco) y la plataforma Snowflake. Los participantes se llevan una solución funcional que demuestra valor tangible desde el día uno.

Relación con el ISF

El ISF (Industry Solutions Framework) es el repositorio centralizado de Snowflake para demos orientadas a outcomes, skills de Cortex Code y assets de GTM por industria. La Cocothon es el "Push Motion" dentro del ISF — un mecanismo estructurado para alimentar el framework con soluciones validadas en campo.

2. Objetivos

  • Demostrar valor real — El cliente resuelve SU problema con Snowflake en una sesión
  • Involucrar negocio + técnicos — Ambos perfiles del cliente participan y validan juntos
  • Acelerar decisiones — Convertir prospectos en oportunidades concretas con evidencia tangible
  • Generar assets reutilizables — Skills, demos, semantic views, agents para escalar
  • Fortalecer relación — Co-creación que genera confianza y ownership del lado del cliente
  • Reducir ciclo de venta — El cliente se lleva un MVP funcional, no una presentación

3. Modalidades

Recomendación: Para una primera Cocothon, la modalidad Standard (3-4 horas) es ideal — suficiente para que los equipos entiendan el reto, construyan, y presenten una solución funcional.

Composición ideal de cada equipo: 1-2 personas de negocio + 1-2 personas técnicas del cliente + 1 SE de Snowflake como facilitador. Esto garantiza que la solución resuelve un problema real Y es técnicamente viable.

Jurado (2-3 personas)

  • Sponsor ejecutivo del cliente (VP, Director, C-level)
  • SE o Industry Principal de Snowflake
  • Partner técnico (si aplica)

5. Estructura del Evento

Pre-evento (1-2 semanas antes)

  1. Selección de cuentas — Baja adopción, oportunidad abierta, caso de uso claro
  2. Problem Statements — 2-7 problemas concretos alineados al ISF
  3. Preparación de datos — Datos del cliente o sintéticos en sandbox
  4. Briefing a equipos — Problem statements, acceso a datos, skills disponibles
  5. Setup técnico — Cuentas HOL, Cortex Code instalado, skills preloaded

Día del evento (formato Standard — 3.5 horas)

0:00 — 0:20
Kick-off (AE presenta): Bienvenida, qué es la Cocothon, agenda, problem statements, criterios de evaluación
0:20 — 0:40
Planificación: Equipos analizan su reto, definen estrategia de solución, priorizan qué construir
0:40 — 2:30
Build: Construcción con Cortex Code (SE facilita, perfiles técnicos implementan, negocio valida y orienta)
2:30 — 2:45
Demo prep: Equipos preparan pitch de 5 minutos (negocio presenta el valor, técnico muestra la solución)
2:45 — 3:15
Show & Tell: Cada equipo presenta su solución + Q&A del jurado
3:15 — 3:30
Deliberación, premiación y próximos pasos

6. Criterios de Evaluación

Los criterios son generales y aplican a cualquier caso de uso independientemente de la industria o el problema específico que resuelva cada equipo:

CriterioPesoDescripción
Impacto de Negocio30%¿Resuelve un problema real del cliente? ¿El beneficio es cuantificable o medible? ¿Quién se beneficia?
Viabilidad25%¿Es implementable en producción? ¿Qué tan cerca está de ser productivo con esfuerzo razonable?
Uso de la Plataforma20%¿Aprovecha las capacidades de Snowflake de forma efectiva? (AI, sharing, marketplace, governance, etc.)
Completitud15%¿La solución funciona end-to-end? ¿Es demostrable? ¿Tiene una experiencia de usuario clara?
Presentación10%¿El equipo comunica el valor claramente? ¿Negocio y técnico se complementan en el pitch?
Nota: Estos criterios permiten evaluar de forma justa equipos que trabajen en casos de uso completamente diferentes (ej: un equipo en supply chain y otro en customer analytics) bajo la misma rúbrica.

10. Post-evento y Scaling

  1. Documentación (misma semana) — SE Champion documenta solución como skill o demo replicable
  2. Handoff a FCTO — Si es generalizable, el FCTO la evalúa e incorpora al ISF
  3. Follow-up con cliente (1-2 semanas) — AE usa resultado como hook para próximos pasos (POC, expansión)
  4. Retroalimentación — Survey a participantes para iterar formato
  5. Playback regional — Compartir resultados en team calls para inspirar replicación

12. Checklist de Preparación

  • Problem statements definidos y validados con el cliente
  • Datos del cliente cargados en Snowflake (o dataset sintético preparado)
  • Cuentas HOL creadas con features habilitados (ver solicitud HOL)
  • Cortex Code instalado y probado por todos los participantes técnicos
  • Skills relevantes preinstalados y funcionando
  • Jurado confirmado (2-3 personas, incluir sponsor del cliente)
  • Premios definidos
  • Sala o plataforma virtual confirmada (buena conexión si es presencial)
  • Invitación con agenda enviada a participantes (2 semanas antes)
  • Briefing previo con los equipos (problem statements + acceso a datos)
  • Datasets de prueba validados (verificar que las queries funcionan)
  • Perfiles de negocio y técnicos confirmados por equipo

13. Mejores Prácticas

Claves para una Cocothon exitosa:
  1. Mínimo 3 horas — El tiempo suficiente para que los equipos entiendan, construyan y presenten soluciones completas
  2. Equipos mixtos (negocio + técnico) — El perfil de negocio valida el valor, el técnico implementa. Ambos son necesarios
  3. Problem statements concretos — No dejarlo abierto; dar contexto de negocio claro y datos relevantes previamente preparados
  4. Pitch de 5 minutos — Fuerza a los equipos a focalizarse en el valor de negocio, no solo en la técnica
  5. Jurado mixto — Liderazgo del cliente + especialistas de Snowflake da credibilidad y perspectiva diversa
  6. Seguimiento inmediato — Documentar resultados y agendar follow-up en la misma semana del evento

14. ISF — Industry Solutions Framework

El ISF es el repositorio central de Snowflake para:

  • Demos orientadas a outcomes de negocio por industria
  • Skills de Cortex Code reutilizables
  • Assets de GTM (decks, battle cards, qualification questions)

Flujo de incorporación al ISF

  1. SE construye demo alineada a necesidades del cliente y al framework ISF
  2. SE contacta al FCTO para agregar al ISF
  3. FCTO valida calidad (outcomes, funcionalidad, alineación GTM)
  4. Se agrega al ISF para uso cross-regional
Para incorporar una solución al ISF: Contacta al Field CTO de tu vertical o al Industry Principal de tu región. Ellos validan la calidad y alineación GTM antes de publicar en el repositorio central.
